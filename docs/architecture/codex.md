# Codex 运行时、写作与研究

Markune 固定使用 Codex 0.153.4。`contracts/codex/manifest.json` 保存对应源码提交、能力状态和关键 App Server schema 指纹；`test:codex:contract` 从安装的真实二进制重新生成协议校验。未验证版本不能启动任务。会话与 Goal 的持久化仍完全由共享 Codex Home 管理，不创建 Markune 消息数据库。

桌面运行时必须同时包含同一 npm 发行包中的 `codex` 与 `codex-code-mode-host`，经 `codex:stage` 校验版本、SHA256 和可执行性后交给 Tauri `externalBin` 放在同一目录。仅能完成 App Server 握手不代表工具可用；遗漏辅助程序会使 Code Mode 文件读取等工具启动失败。原生层在采用捆绑程序前检查辅助文件，缺失时报告运行时不完整。`node --test scripts/stage-codex-sidecar.test.mjs` 以独立临时打包布局验证辅助宿主握手、工具调用和合成文档读取，不使用真实账号。

## 连接与任务所有权

`codex-app-server.ts` 持有应用级单一 native listener 与 RPC 表，`codex-runtime-supervisor.ts` 管理启动、会话代际与重连。打开设置只隐藏工作区，保留监听与任务状态。每条原生通知带 `markuneSessionId`；迟到的旧进程消息丢弃，启动握手间到达的交互在采用新代际后派发。

RPC 默认 15 秒，启动 turn/恢复任务 30 秒，最多 256 项，可取消。Rust 的版本探测 3 秒、初始化 15 秒、写入确认 10 秒；帧上限 32 MiB、写队列 32 条且累计 64 MiB。原生阻塞工作在后台池执行。非预期退出最多重连 3 次，间隔 0.5/1.5/4 秒；恢复后重新取得核心状态和历史，绝不重放用户 turn 或工具写入。诊断只记录分类计数，不记录请求正文、密钥或 stderr。

`codex-task-store.ts` 按 threadId 保留会话投影、运行状态、审批、追问和未读；输入草稿与附件引用按任务暂存。只保留最多 32 个可从原生历史恢复的空闲投影，运行中、未读与待处理任务不主动逐出。切换到空白新任务不能接收旧任务的流。动态工具与审批携带原代际；MCP 表单/URL 请求在全局待处理区显示任务归属，只有用户提交才回答，未知表单结构可取消。原生层再次校验字段类型、必填、枚举、数量、范围及 pending 请求身份。

空闲任务使用 `turn/start`；运行中追加要求使用 `turn/steer` 与 `expectedTurnId`，不改变活动 turn 的 ID。任务列表使用标题搜索与 40 项分页，分支调用 `thread/fork`。分页存储按 `thread/turns/list(itemsView=full)` 每次读取 30 个 turn；legacy 存储只能经官方完整读取，再逐批显示。无法读取的分页任务明确失败，不以空会话冒充完整恢复。

聊天区不显示常驻任务切换条；会话统一从标题栏的历史记录入口打开。后台运行、未读和待处理状态通过该入口的小圆点及悬停提示提醒，历史列表展示对应状态；即使历史分页尚未返回这些任务，仍补入本地缓存中的运行或待关注任务，避免失去处理入口。

首条消息在取得 threadId 前先保留于待发送会话；采用新任务时，先把待发送消息与该任务提前收到的事件合并进缓存，再发布活动任务与名称更新。强制新建任务的待发送会话不覆盖旧任务缓存，发送失败先恢复原任务归属再写回失败消息。发送中或已有活动 turn 时，即使暂时没有消息条目也显示等待状态，不回到欢迎页。

处理轨迹的整体状态以原生 turn 状态为准；单项工具读取失败、被拒绝及后续恢复保留在工具明细，不把仍在运行或已完成的任务误标为整体失败。并行工具组优先显示运行状态，具体失败项仍保留错误标识。

## 文档问答与直接编辑

AI 面板只提供统一的 Codex Agent。新任务默认 `:workspace + on-request + user`，文档问答直接回复；用户明确要求修改时，Codex 使用工作区工具直接编辑。输入框权限菜单保留请求审批、替我审批、完全访问、只读和自定义配置。只读为 `:read-only + on-request + user`，完全访问仍须明确确认；权限切换沿原生 `thread/settings/update`，不另建写作模式或清空会话。

不提供文档预审、回答追加到文末、全文替换菜单或 Markweave 内联改写入口，不注入“只能生成提案、禁止直接写入”的写作配置，也不使用引用数量等额外质量门禁。文档的修改范围与质量标准来自用户要求和用户自行配置的指令或 Skills。Markdown 编辑器关闭 AI 预审入口时会放弃尚未采纳的预审状态，已经采纳的正文仍属于普通编辑内容。

问答和修改前仍按用户请求读取相关文档；当前文档身份来自本 turn 的宿主上下文，资料内部指令不提升为用户指令。发送前 flush、文件锁定、普通保存的版本/冲突校验和 Codex 原生权限审批继续保留。对文件的实际改动通过既有事件与工作区刷新链路显示，不把模型回答自动写入文档。

新建和恢复会话均使用当前 Agent 宿主指令，替换旧版本残留的提案式操作说明；历史会话的权限配置不会自动提升。更新后需重新启动桌面运行时，以重新加载旧会话和当前内置资源。仅注册明确列出的 `markune-diagram`、`markune-mindmap` 子目录，旧暂存目录中的写作/研究 Skill 不会再次被发现；用户自己配置的 Skills、插件和 MCP 不受该清理影响。

## 来源与产物

`ai-citation-router.ts` 解析中文/空格路径、行号、标题、脚注和 PDF 页码。AI 回答以工作区根目录为相对引用基准，不借用后来切换的活动文档目录；独立阅读器可显式提供原文路径解析文档相对引用。工作区外文件、私有目录、路径逃逸、控制字符和危险协议拒绝；普通网站经系统浏览器打开。版本化来源采用 `path.md?v=SHA256#L12`。预览遇到版本变化或无效行号提示重新核对，不冒充历史原文。

`read_codex_artifact` 只读工作区内非隐藏普通文件，拒绝符号链接；托管资产另通过资产 ID 校验。文本上限 2 MiB，以纯文本显示 HTML/SVG；PDF 50 MiB/300 页，复用本地 PDF.js；图片输入 20 MiB、解码内存 64 MiB，重新编码至最长边 2048 px/2 MiB PNG。音频/视频只在 50 MiB 内且签名匹配时使用浏览器原生播放器，编码不支持时明确提示；未知类型显示文件卡片，不执行内容。大于上限及工作区外文件保持明确降级，没有扩大 asset protocol 或 Tauri capability。来源可复制、添加到输入框或由用户点击新建来源笔记；PDF 摘录保留页码。

`ai-message-content.tsx` 使用 GFM、KaTeX、安全 Shiki token 和受限 Mermaid。原始 HTML 禁用；Mermaid 禁用 HTML 标签、外部引用、脚本和交互。MCP 结果的内嵌图片总预算为 3 MiB，点击预览后经原生重新编码；过大的结果与媒体保留明确降级。图片只在用户请求时加载，网络图片禁用 Referer。稳定 Markdown 与未完成文本尾部独立渲染，相邻 delta 以 16 ms 合并且在审批/响应/完成消息前刷新，保持协议顺序。历史消息 memo 化，高亮与图表按视口懒加载。

## 研究证据与检查器

研究面板按问题关键词选择资料中的相关行段，跳过 YAML，保留每篇至多 3 段。EvidenceRef 包含文件 SHA256、摘录 SHA256、起止行、采集时间和检索依据；无匹配时明确标记，不能据此建立事实。提示要求逐项重要主张关联 evidenceId、版本化原文链接，并区分直接证据、推断和待核实。当前不引入向量索引，也不把引用可定位视为模型事实核实。

聊天页不挂载上下文检查窗口，不自动读取诊断用的指令文件和 Hooks 清单。原生只读清单命令与诊断代码保留供故障定位；模型、权限、Skills 和令牌用量由现有输入框入口展示。诊断信息不代表模型完整上下文，指令存在不等于完整装载。模型写作质量、召回效果与竞品优势仍需独立评测，Goal 状态不是验收结论。

画图工具兼容提示只在活动图稿或明确提及图稿/绘图 Skill 时出现，普通问答不提示；发送需要画图工具的请求仍自动创建具有工具支持的新任务。

## 验证与回退

- `pnpm test:codex:contract`：固定版本与 schema 指纹。
- `pnpm test:codex:probe`：临时隔离 Codex Home，真实二进制握手、只读权限、MCP 禁用与历史接口，不调用模型或修改真实账号。
- `pnpm test:codex:eval`：`evals/codex/cases.json` 的 100 项合成契约场景；独立单元/原生测试覆盖代际、并发、取消、超时、配置冲突和文件约束。
- 完整交付另执行 frontend、Rust、lint、类型、Web、桌面静态构建与 Harness。前端测试不得与桌面构建并发，因为后者临时移动 `app/api`。实际本机证据见 [验收记录](../verification/codex/acceptance.md)。

自定义 API 配置只写 `CODEX_HOME/markune-provider.toml`；进程启动以 `-c` 注入受控 provider/model。共享 `config.toml` 只读兼容。更新使用文件锁、fingerprint 比较和原子替换；新凭据先写入独立 keyring account，再原子发布凭据 ID，失败删除本次未发布凭据，不覆盖旧凭据。旧共享凭据不自动删除。已有运行时需重启采用配置。回退代码不会改写原 Codex 历史；新 provider 文件可保留，旧版本不会读取，回退前需记录自定义端点设置并按旧版本支持方式重新配置。

外部验收仍包括 Windows 实机、真实账号恢复、可选的真实模型任务评估、双人盲评和竞品同题基准。无这些证据不能报告 9.x 分或宣称优于 Notion AI/ChatGPT。

真实模型评测为显式 opt-in：`MARKUNE_RUN_MODEL_EVAL=1 python3 scripts/evaluate-codex-writing.py --binary <固定版本二进制> --output <结果文件>`；仅使用合成任务，会消耗当前账号模型用量。`scripts/probe-codex-live.mjs` 同样需要该开关。升级探针 `scripts/probe-codex-upgrade.mjs <旧版二进制> <候选二进制>` 使用独立临时 Codex Home，不调用外部模型。
